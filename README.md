# PageMortem

A Firefox sidebar that uses your own local model servers to ask about, summarize, translate and operate web pages. Extension-page model requests are locked to origins chosen at build time. Webpages still make their own network requests, and approved image saves use Firefox's downloads API.

## Install (Firefox Developer Edition)

1. Lock it to your server and build the package:
   ```
   python configure.py http://<main-server-ip>:<port> http://<optional-vision-server-ip>:<port> http://<optional-decision-server-ip>:<port>
   ```
   Include each server used for text, vision, reranking or decisions (omit unused examples). The build accepts loopback, private LAN IP addresses and `.local` names; custom public DNS names are refused even if they point into your LAN. This copies the extension into `build/` with the lock set, and packages that copy as `pagemortem.xpi`. Server addresses go only into those two, which git ignores; the `manifest.json` in the repository keeps a placeholder. Re-run it whenever an allowed server address or the code changes.
2. In `about:config`, set `xpinstall.signatures.required` to `false` (Developer Edition and Nightly only).
3. In `about:addons`, open the gear menu, choose **Install Add-on From File…** and pick `pagemortem.xpi`.
4. Open the sidebar with the toolbar button or **Alt+Shift+L**. Go to **Settings**, enter the endpoint (for example `http://192.168.1.50:8080/v1`), then click **Test connection**.

**Updating:** re-run `configure.py`, then install the new `pagemortem.xpi` the same way, over the installed one. Don't remove PageMortem first: Firefox deletes an add-on's settings and skills when it is removed. Before a reinstall, use **Settings → Backup → Export backup**, and afterwards use **Import backup…** to restore everything. The backup file includes your API key.

For quick iteration you can instead load `build/manifest.json` from `about:debugging` → **This Firefox** → **Load Temporary Add-on**. That copy is removed when Firefox restarts. After editing code, re-run `configure.py` and click **Reload**: `build/` is a copy, so edits to the source don't reach it until then. (Loading the top-level `manifest.json` works too, but its placeholder lock blocks your server.)

## Server notes

- **llama.cpp `llama-server`:** start it with `--jinja` so tool calls work. Add `--mmproj` for a vision model. Use `--host 0.0.0.0` so other LAN machines can reach it.
- **vLLM:** use `--enable-auto-tool-choice --tool-call-parser hermes` for Qwen models.
- **Reranker (optional).** Put a reranker such as Qwen3-Reranker in **Settings → Rerank model** if your server serves one on `/rerank` (vLLM, llama.cpp with `--reranking`, Infinity). When a page is too long to send whole, Ask then sends its start plus the passages most relevant to the question, instead of cutting it at the end, and Sources places reworded points without asking the main model. Use **Check Rerank** to test it.
- **Decision model (optional).** Choose **System One** for Halogen D3 (`d3-lite` or `d3-nano`) or **OpenAI structured output** for a model that supports `response_format` with a JSON schema. These are separate interfaces; choose the one your server actually serves. Agent watches can then wait for a condition, such as a time passing or a price dropping below a limit, instead of exact text. Image decisions use `/systemone` when available and fall back to vision for unavailable or ambiguous results. Use **Check Decision** to test text and image support independently.
- **Qwen3-Next is text-only.** For image tasks, run a Qwen3-VL model too and put its name in **Settings → Vision model**. If your main model accepts images, leave that field blank.
- If Agent mode stalls, or tool calls show up as plain text, switch **Tool calling** to *JSON in text*.

## Using it

- **Ask** answers from the included pages. To compare pages, select several tabs first (Ctrl+click or Shift+click the tabs), or add an open tab through **Context**. Selected text is included automatically unless excluded there. Turn on **Keep earlier pages** inside Context to retain pages as you browse; otherwise only the current selection of tabs and pinned snapshots remain.
- **Summarize** works on the page, or on the selection if one exists. Long pages are summarized in parts. The picker next to it sets the length and is remembered: **Brief** (TL;DR plus 3 points), **Standard** (TL;DR plus 3–7 points, up to 10 for long pages) or **Detailed** (sections with headings, about 8–15 points, up to 25 for long pages).
- **Translate** translates the selection into the sidebar. With no selection it translates the whole page in place, and **Show original** reverts it.
- **Agent** remembers the conversation's earlier tasks (each task, its skill, its answer and the page it ended on; the last five), so *again* or *now the next page* works. It does not keep their page contents or approvals. **Agent** reads the page, searches long pages for text, opens links in background tabs, clicks, presses keys, scrolls, waits for slow pages to load, looks at screenshots (images get numbered labels) and highlights what it finds. Search sees only what reading the page does (never password or payment field values, nothing hidden). A highlight outlines the whole row when the match is in a table, follows the page as you scroll, and stays for 30 seconds; press Esc or click the page to clear it. It asks before anything risky and closes uncited tabs it opened when it's done.
- **Skills.** Add one in Settings, import one markdown file, or import a folder. A folder is a skill directory: `SKILL.md` plus other files (`references/`, `assets/`). Those files are stored with the skill; `scripts/` (PageMortem never runs them), hidden files and files over the size limits are skipped, and the import lists what it skipped. A skill stays on this computer until you use it. In the sidebar, start a message with the skill's name: `@krea2-caption caption this image`. The skill then stays active for your next messages, shown as a chip above the message box, until you name another skill, click the chip's ×, or start a new conversation (an agent skill stays idle in Ask mode). An `@` anywhere else is ordinary text, and an unknown `@name` at the start is refused. A **prompt** skill answers once in either mode: its instructions and every supporting file are the system prompt (files together at most 16,000 characters), and any request with images (a screenshot it needs, or example images in the skill) goes to the vision model when one is set. If the model rejects images, it answers again without them. Choose **Raw text** so a caption format is not rendered as Markdown. Its answer is not part of the Ask conversation, but the skill sees its own last three answers, so *again* or *make it shorter* works. An **agent** skill needs Agent mode and only adds instructions to it. The agent sees a list of the skill's files and reads one with `read_skill_file` when it needs it; example images are shown to the model once, or described once by the vision model when one is set, so a text-only main model still works. A skill cannot approve an action or contact any server other than the locked one. A file may start with a `---` header of `name`, `description`, `kind` (`prompt` or `agent`), `needs` (`none`, `image` or `page`) and `output` (`raw` or `markdown`); otherwise the file name, or the folder's `SKILL.md` name, is the skill name. Without `kind`, a folder with text reference files is imported as an agent skill and anything else as a prompt skill. A folder import keeps files up to the agent limit whatever the kind, so you can change the kind before saving; a prompt skill over its 16,000-character limit is shown with a warning and cannot be saved until it fits or becomes an agent skill.
- **Saving images.** Ask the agent things like *save all images of kittens chasing laser pointers* or *download every photo on this page*. PageMortem scrolls through the page, crops each image from a screenshot and asks a yes/no question about it: the decision model, if set and it reads images (d3-lite does, through the server's `/systemone` endpoint, in about 0.1 s each), otherwise the vision model or the main model. If the decision model can't take images, the run says so once and uses the vision model for the rest. Only the decision model's clear answers count (a score below 0.15 or above 0.85); images it is unsure about go to the vision model. When recognising a match takes knowledge rather than just looking (a named person, a brand or logo, a specific product model, an artwork, an artist, or an art movement such as Cubism; broad looks such as *abstract* or *black-and-white* stay with the decision model), the agent marks the request precise and every image goes to the vision model. Many vision models won't say who a real person is; those replies count as no match, and the agent tells you so. It then saves the matches to `Downloads/PageMortem/<what you asked for>/`, numbered in page order. Matches appear as thumbnails in the sidebar. It saves the best version the page offers: the full-size file when a thumbnail links straight to one, otherwise the largest `srcset` entry, but only when that file is on the page's own site or the site the image is shown from; otherwise it saves the image as displayed. Requests carry only the page's origin as Referer. Images drawn by page script (`blob:`) and inline `data:` images are skipped. The first save asks once, and Firefox asks for its download permission at that moment; only downloads reported with a supported raster MIME are kept (SVG and files with no reported type are deleted; file bytes are not verified).
- **Watching a page.** Ask things like *add it to the cart when it's back in stock*. The agent asks once, then watches the page for as long as you ask (30 minutes if you don't say; the sidebar must stay open and the computer awake): it checks the page live as it changes and reloads it every 15 s to 10 min (30 s by default). It looks for text that marks the change, or, with a decision model set, for a condition such as *the price is below $50* or *the clock shows 11:49:00 PM or later*. The decision model judges a condition each time the page text changes (at most about once a second, on the first 16,000 characters). The checks run in PageMortem's own code, so a long watch makes no main-model calls and counts as one step. Page text could talk the decision model into an early "yes"; that only ends the watch, and the agent reads the page again before doing anything. When the change appears you get a Firefox notification (the first watch asks for that permission; you can decline and still watch) and the agent carries on. If you asked for the item to be added to the cart, the watch card may preapprove one click on a specific existing Add to cart button. That grant lasts 60 seconds after a literal page change and only while the tab, address, document, button and captured product/form context stay unchanged. A reload, a model-judged condition, or a newly appearing button requires fresh click approval. The snapshot cannot prove what site JavaScript will do; approving the action accepts that uncertainty. The grant is not used if the button's link or form goes to a checkout or payment address, and if the click lands on a checkout or order page the agent stops there and notifies you. Anything else, such as *Buy now*, a second Add to cart or checkout, still asks you, so nothing is bought while you're away. The watch stops if a reload lands anywhere other than the watched page (a sign-in or error page could otherwise look like "Out of stock" going away), after three failed checks in a row, at its time limit, or when you press Stop.
- **Extract text** transcribes the text in the main image on screen, with no prompt to write: the largest image in view when it fills a good part of the view, otherwise the visible part of the page (useful for canvas text, PDF viewers and video frames). To pick one image, right-click it and choose **PageMortem → Extract text from image**. The capture keeps up to 2560 pixels of width, far more than Ask's screenshots, so small print stays readable. It goes to the vision model when one is set, otherwise to the main model, which must accept images. The text appears as plain text with a copy button; unreadable parts are marked `[illegible]`. Only the part of an image inside the window is read, and images inside frames aren't supported (it reads the main image instead).
- **Copy as Markdown** converts the page's main content, or the selection, to Markdown on your computer, without a model, and copies it. Nothing is shortened or reworded. Headings, lists (including task lists), links, images, code blocks and quotes are kept. Tables become Markdown tables: merged cells are filled in, a header that spans two rows is joined per column (*Orbit / AU*), and grids built from `div`s with table roles count as tables. Tables used only for layout (one column, or a table inside another) are read as ordinary text. Site navigation, hidden text, form controls, small icons and inline `data:` images are left out. Tables the rules may get wrong (rows of different lengths, merged cells in the data, a header over several rows, no header row, lists inside cells, mostly empty cells) are sent to the model one at a time, as their HTML without classes or styles, at most 8 per page. A redone table replaces the converted one only if it is a single well-formed table with exactly the original's words: none added, none missing (merged values may repeat). Otherwise the converted table is kept and a note says why. Stop keeps the remaining tables as converted. The result is copied when it's ready (PageMortem asks for the clipboard-write permission for this), and the copy button under it copies it again.
- **Group tabs** sends the titles and addresses of this window's unpinned, ungrouped tabs to your model, which sorts them into named, coloured groups. Nothing changes until you click **Create groups** on the suggestion card; tabs that fit no group, and tabs closed, pinned or grouped in the meantime, are left alone. Needs Firefox 139 or later.
- The right-click menu has Translate, Summarize and Ask entries, and Extract text on images, plus **Run @name** for each skill shown as a button. Right-clicking an image lists the button skills that can use it, as **Run @name on this image**: prompt skills that include a screenshot get that image instead of the main one, and agent skills get it with their task (described once by the vision model when one is set, so a text-only main model still works). PageMortem first tries the image's full-size file (a file the thumbnail links to, else its largest `srcset` entry), downloaded by the page's content script with the page's cookies and only its origin as Referer, and only from the page's own site or the displayed image's site. The file must be a raster image under 15 MB and arrive within 4 seconds; it is scaled to at most 2048 px. Otherwise, or when it redirects to another site, the image is cropped from the screen as Extract text does, and a note says which was used.
- **Skill buttons.** Tick **Show as a button** on a skill in Settings (at most 4) to add it after the built-in buttons and to the right-click menu. A click runs the skill once on the current page without making it the active skill. Text in the message box (or, from the right-click menu, the selected text) becomes its task. An agent skill's button has a dashed border and switches the sidebar to Agent. **Settings → Sidebar buttons** hides built-in buttons you don't use; their right-click entries stay.
- Each reply ends with its speed and size (tokens per second, tokens in and out, cached prompt tokens). Hover for time to first token, prompt speed and speculative-draft acceptance. Numbers come from the server when it reports them (llama.cpp-style `timings`, or `usage`); otherwise they are estimated and marked `~`. Turn this off in Settings.
- When an agent click is flagged only because of its label (for example “Close”), the card also offers **Always allow “Close” on this site**. That choice lasts until you start a new conversation or close the sidebar, and covers only that exact label on that site. It is never offered for purchases, deletions, messages, account, password, subscription or permission actions, cancel/reset/disable/save/update controls, form submissions, downloads or risky link addresses.

### Multi-page exploration

Agent's `open_link` accepts up to five links per call and loads and reads up to three pages concurrently in background tabs. Results stay in requested link order, and the current tab stays unchanged. Site, download, and redirect approval prompts are handled one at a time. A denied or failed link does not discard other results; Stop cancels the batch and waits for workers to settle before cleaning up agent-created tabs.

### Sources

**Ask and Summarize** answers are plain text; the model isn't asked for citations. Sources appear only when you ask for them. Hover a paragraph or bullet and click **source**, or select part of an answer and click **Show sources**. PageMortem matches each point to the page sentence it most likely came from, on your computer, using the page text the answer was based on. With a rerank model set, the reranker judges the likeliest sentences for each remaining point first (every sentence on a short page), which places most reworded points without a model call. Only points still without a clear match go to the model, which is shown the nearest passages and asked for the exact supporting sentence. A sentence the model gives is used only if it appears word for word in the page text. Otherwise the closest weak match is shown, or **Not found on the page** when nothing matches. A match is not proof that the passage supports the point; check the surrounding context.

**Agent** answers carry inline passage citations. Select a numbered citation to jump to the passage in its source tab. Citations are listed once per source page under **Sources** below the answer. Quotes must match the source text sent to the model, allowing whitespace differences only. Unknown sources and mismatched quotes are listed as **Unverified**, without a Show on page action.

**Show on page** highlights the passage for 30 seconds. Press Esc or click the page to clear the highlight.

The quoted snapshot stays with the reply. Show on page reports closed or navigated tabs, reloaded documents, missing or hidden passages, and quotes that occur more than once instead of highlighting an approximate match. It does not reopen tabs or search other pages. Quotes within open shadow roots are supported, but quotes spanning different DOM roots are not. Agent keeps tabs referenced by valid final citations open for verification.

### Context and modes

Expand **Context** to inspect Ask's sources, URLs, read times, selected excerpts, and the character budget used for each page. Truncated sources are marked. With a rerank model set, a page too long to send whole is cut differently for each question: its start plus the passages most relevant to the question (and the one before it), and a note under the answer says so. A follow-up that needs other passages sends the page again. Unpinned open sources are reread before each Ask request.

- **Pin snapshot** keeps that copy of a page through navigation. **Add an open tab** adds it as a pinned snapshot.
- **Refresh** updates one source; **Refresh context** updates included sources whose tabs are still open at the same address, including pinned ones. Closed or navigated-away snapshots remain unchanged.
- **Remove** excludes a page from future Ask requests. **Remove selection** excludes the extra highlighted excerpt, not matching text in the included page. Selected excerpts share a 6,000-character limit.
- Removing a source or changing selection inclusion clears model conversation history, including earlier answers, so removed information is not retained there. Existing messages stay visible in the sidebar. Manual refresh also clears model history.
- **New conversation** clears the source overrides and remembered approvals, then includes the currently selected tabs again.

**Ask** reads the included pages without interacting with websites. **Agent** starts on the active tab and can use Firefox-selected tabs; Ask's source list does not restrict its navigation. The mode description stays above the message box. Use arrow keys, Home, or End to change modes when a mode button has focus.

Approval cards identify the site, target and available action details, with buttons such as **Submit form**, **Type text** or **Start watch**. Form approvals explicitly warn when submitted values cannot safely be enumerated. Detected consequential actions still require individual approval; ordinary controls can also trigger site-script side effects.

### Settings and capability checks

Settings are grouped into **Connection**, **Models and capabilities**, **Safety**, and a collapsed **Advanced** section for generation, context, translation concurrency and screenshot tuning.

**Check Text**, **Check Tools**, and **Check Vision** send separate diagnostic requests using the displayed settings without saving them or sending page content. Tools checks validate a returned call and its argument in the selected native or JSON-in-text mode; no browser tool is executed. Vision checks send a generated two-color image to the vision model, or the main model if no override is set. A pass confirms only that small probe, not reliable behavior for every task; a failed probe does not establish that the capability is unsupported. Choose **Save settings** to apply changes. The packaged network lock remains unchanged.

## What "local only" means here

- **Network lock.** The extension-page Content Security Policy (`connect-src`) permits model requests only to the local origins passed to `configure.py`; settings cannot add another origin. Model fetches reject redirects so an API key is not forwarded to another endpoint. This lock does not restrict normal webpage traffic, browser navigation or Firefox's downloads API. DNS and server behavior remain outside the extension's control.
- **Page access.** The `<all_urls>` host permission lets PageMortem inject into, read and operate ordinary HTTP(S) tabs when granted in Firefox. That is broad access; it supports autonomous navigation, background tabs, reloads and multi-site research. Page content is sent to the configured local model servers during use. The content script itself makes no requests, but visited pages do.
- **Navigation.** `open_link` opens an existing page link in a background tab. `go_to` can open a model-supplied HTTP(S) address after showing the full address for approval, including same-site paths. The agent has no arbitrary request or script execution tool. GET navigation and page scripts can still have side effects.
- **Approvals are enforced in code** (`lib/agent.js`), never by the model:
  - Existing links opened with `open_link` are navigated to without firing page click handlers. Clicking or pressing keys on a page control asks first unless the user has granted ordinary interactions on that site.
  - Key presses are limited to Escape, Tab, arrows, PageUp/PageDown, Home/End, Enter and Space, always on a numbered element. Letters and Ctrl/Alt shortcuts are refused, since on many sites they archive, delete or send. Enter or Space on a control gets the same approval as clicking it, and Enter in a field the same as submitting it.
  - Asked every time, with no "allow all" (the one exception is an Add to cart click you approve together with a watch; see *Watching a page*): downloads, form submissions, buttons in forms that send data, anything whose label or link address suggests a change (buy, delete, send, save, continue, …), typing into non-search fields, and using a tab you didn't select. With **Ask before going to a different site** enabled, leaving an approved site also asks; turning it off permits cross-site links and redirects without a separate site approval.
  - "Allow all" exists only for scoped interactions on one site and searches. An ordinary interaction grant accepts the possibility of site-script side effects; labels cannot establish that a control is read-only. A search grant covers one search box (its label and where its form sends) on that site; a field counts as a search box only when it is itself `type=search` or `role=searchbox`, or sits in a GET form marked `role=search`.
  - Labels and link addresses come from the page. They can raise suspicion, but cannot establish that an action is safe.
- **Checked again at the last moment.** Each action is bound to the document and an element fingerprint; changes to those recorded properties invalidate approval. This cannot predict or undo site JavaScript, hidden application state, a request fired by a pointer or key handler, or a network request made during a redirect. After actions, PageMortem checks where the tab landed. With cross-site approval enabled, it asks about an unapproved site before reading it; declining sends the tab back or closes a tab it opened.
- **Notifications** (optional `notifications` permission) are used only to tell you a watched page changed.
- **Downloads** use Firefox's downloads API (optional `downloads` permission, requested the first time you approve a save). That API isn't bound by the network lock, so it is used only for image addresses already shown on approved pages; the model can't give it an address of its own. PageMortem rejects non-raster filename extensions and downloads whose reported MIME is not a common raster type. Firefox does not give the extension file bytes to validate, so a server that lies about the MIME may still leave a disguised file in Downloads.
- **Sensitive fields.** Recognized password, payment, ID and credential fields (API keys, access tokens, secrets and recovery codes) omit their values from agent page reads and refuse typing and key presses. Detection uses field type, autocomplete and label/name/ID hints, including spaced, hyphenated, underscored and camelCase credential names. This is not general secret detection: credentials displayed as ordinary page text or in screenshots can still reach the model.
- **Stop** (Esc) cancels the run, prevents pending page calls from dispatching actions after cancellation and closes tabs the agent opened. Tabs you opened are never closed. Actions already sent to a page may still complete; Stop does not undo page events or their effects. Model and page calls also have timeouts, and agent runs have a step limit.
- **Links in answers** are clickable only when their full canonical URL exactly matches a page PageMortem read for that answer. Other links are shown as plain text. A page already read may itself contain sensitive data in its URL, and following a link can still redirect or trigger website requests.
- **What can still reach a website:** pages the agent visits load like any page you visit. Text the agent types into a field (with your approval) is visible to that site. A translated page's own scripts can read the translated text. A page's scripts can react to anything PageMortem does on it; PageMortem detects where that leads, but can't stop the page from sending its own requests.
- **Prompt injection:** page text is handed to the model labelled as untrusted data, and the system prompt tells it to ignore instructions inside pages. A small model can still be fooled, which is why every gate above is enforced in code rather than left to the model.
- **Site boundaries** use a built-in list of shared-hosting and country suffixes (e.g. `alice.github.io`, `x.vercel.app`, `bbc.co.uk`), not the full Public Suffix List. A rare platform not on the list is treated as one site.

## Tests

```
npm test                                                     # offline: agent policy, parsing, Markdown, client
PAGEMORTEM_ENDPOINT=http://<server>:<port>/v1 npm run test:live # also exercises a real model server
PAGEMORTEM_HALOGEN_ENDPOINT=http://<server>:8731/v1 npm run test:halogen # optional D3 and reranker checks
GECKODRIVER=/path/to/geckodriver FIREFOX_BINARY=/path/to/firefox python tests/firefox_integration.py # optional: installed Firefox extension and real DOM
PAGEMORTEM_HALOGEN_ENDPOINT=http://<server>:8731/v1 GECKODRIVER=/path/to/geckodriver python tests/firefox_integration.py # also exercise Halogen diagnostics in Firefox
```

The Node tests run extension scripts against simulated browser APIs and a minimal fake DOM. The live model suites use the real model client and synthetic prompts or pixels, but still simulate browser APIs; the Halogen suite checks both D3 models' text and image System One responses and the reranker. Its watch diagnostic prints uncertain answers without treating them as a pass. The optional Selenium test installs a freshly built extension in an isolated Firefox profile and checks real content-script injection, event behavior, cross-origin form submission, redirects, screenshot capture, permission revocation and extension-page CSP. It needs no model for those checks. With `PAGEMORTEM_HALOGEN_ENDPOINT` set, it also runs the options-page model diagnostics against Halogen. It does not yet cover sidebar lifecycle, screenshot processing, actual downloads or upgrades.
